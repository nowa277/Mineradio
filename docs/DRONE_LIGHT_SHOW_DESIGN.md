# 火星灯光秀设计

日期：2026-07-07

## 目标

- 在视觉控制台“预设与存档”中新增“火星灯光秀”，位于“安魂”之后。
- 模拟大型无人机灯光阵列，以 12–20 秒间隔轮播图案，并尽量在强拍开始变形。
- 图案持续随节拍呼吸，强拍产生局部提亮、轻微扩散和快速归位。
- 当前版本只收录已验收的三幅图案：`MARS CONCERT` 文字与徽标、玫瑰花束、人物与猫；星群、鲸鱼/动物留待后续版本。
- 每完成一张图案，先通过 Codex Browser 在独立轻量预览页动态验收，确认后再继续。

## 视觉边界

- `MARS CONCERT` 使用用户参考图中的尖锐哥特轮廓字体，并保留下方几何徽标。
- 其它图案优先使用干净的程序化矢量轮廓；参考图含有难以规则化复刻的不对称灯点轨迹时，可离线提取高亮坐标并固化为本地数据，不在运行时加载或展示参考图片。
- 后续 3D 升级方向：从正面二维灯牌升级为可移动镜头观看的 3D 无人机雕塑；正面仍保持三幅图案的识别度，但允许为立体结构牺牲少量像素级复刻精度。
- 图案本体不主动旋转展示侧面；体积感主要在用户拖动镜头、镜头移动观看或双击回正前后的视角变化中体现。
- 舞台歌词保持前景，无人机图案自动后移、降低亮度和辉光。
- 3D 歌单架打开时沿用现有背景压暗规则，无人机层不能浮到歌单架前景。
- 不修改电影视觉系统、播放器玻璃质感或现有预设表现。

## 3D 雕塑化升级方案

目标是在不重写现有视觉系统、不增加通用编辑器的前提下，将当前三幅图案从“固定二维灯牌”升级为“分层无人机雕塑”。

采用方案：语义分层雕塑化。

- 保留当前图案路径、填充、分组和 GPU 粒子变形框架。
- 将采样结果从近似 `x/y` 平面扩展为带稳定 `z` 深度的目标点。
- 每张图案增加 `depthProfile` 或等效深度规则，按 outline、fill、core、spark、trace 等语义分层。
- 图案切换时同步 morph `x/y/z/group`，避免变形过程塌回二维。
- shader 中的节拍呼吸围绕稳定深度层做轻微前后扩张，不再只使用随机 `z` 抖动。
- 默认正面构图稳定，用户拖动视角时露出厚度、层级和空间编队。

三幅图案的深度边界：

- `MARS CONCERT`：文字外白边最前，文字填充略后；徽标外轮廓前层，徽标内部填充中后层；少量背后冷色散点作为空间参照。
- 玫瑰花束：花瓣外圈前层，花芯和内瓣错层；花茎中后层并带轻微 S 形深度变化；星芒远近分布。
- 人物与猫：人物轮廓保持中层，发丝和肩线前层；身体与衣服边缘中后层；猫与人物错开前后关系，尾巴保留深度弧线。

性能边界：

- 继续复用一个 `THREE.Points`、同一套 GPU Buffer 和固定粒子索引。
- 不以无限增加粒子数解决立体感；优先通过语义深度、镜头视差和 shader 呼吸提升质感。
- 默认档兼顾 60 FPS 与明显 3D 感；高性能档可增加远层星点、航迹和更强深度；低性能档削弱附加层，但不得退回纯二维灯牌。
- 不新增网络访问，不上传参考图，不触碰账号 Cookie 或隐私数据。

实施记录：

- 2026-07-07 已将三幅图案的采样点扩展为稳定语义深度：`MARS CONCERT` 正式层 `zRange≈1.69`，玫瑰 `zRange≈1.56`，人物与猫 `zRange≈1.26`。
- 2026-07-08 已验收预览页上下翻转镜头：`yaw` 无限累积，`pitch` 支持接近完整垂直环绕，滚轮缩放和双击回正保持可用。
- 正式层取消图案自身的慢速自动旋转；节拍只驱动深度呼吸、亮度和轻微扩张。
- 独立预览页支持拖动画布 360° 环绕查看侧向厚度，双击回正；图案本体仍不主动旋转。
- 新增测试覆盖三幅图案的非平面深度，防止后续回退为二维灯牌。

## 技术方案

采用矢量路径采样和 GPU 粒子变形：

- 图案由路径、少量填充区域、颜色分组和粒子权重组成。
- 启动时将路径均匀采样成归一化无人机目标坐标。
- GPU Shader 处理呼吸、亮度、纵深、漂移和图案间变形。
- 无人机使用独立 `THREE.Points` 图层，不改写现有封面粒子几何。
- 离开预设后停止更新并释放不再需要的临时缓冲区。
- 图案资源失败时回退到稳定星群图案，不影响播放器和其它视觉预设。

建议文件：

- `public/drone-preview.html`：独立预览入口。
- `public/drone-show.js`：采样、变形、节拍、镜头与颜色运行时。
- `public/drone-patterns.js`：内置图案路径与颜色数据。

预览页只加载 Three.js、无人机运行时、图案数据和必要控件，不要求启动完整 Mineradio 交互。它提供当前图案、节拍开关、BPM、节拍强度、手动强拍、颜色模式、粒子密度和镜头重置。

正式接入时复用同一套图案数据与核心计算逻辑，由 Mineradio 传入真实音频参数、封面颜色和性能档位，不复制一套实现。

## 动画数据流

1. 当前正式预设固定使用 24,000 个粒子。
2. 加载当前图案的目标坐标和参考色。
3. 粒子分批起飞，在约 1.8–2.6 秒内组成图案。
4. 图案保持轻微纵深漂移并随每拍呼吸。
5. 每约 11 秒选择下一图案，并在约 1.45 秒内平滑换形。
6. 变形时部分粒子先脱离形成航迹，再落入新轮廓。

音频映射：

- 低频控制整体呼吸和轻微前后推进。
- 中频控制轮廓内部亮度流动。
- 高频控制少量无人机闪烁。
- 强拍控制局部亮度脉冲、短暂外扩和归位。
- 无音频时使用内部平滑时钟保持微弱呼吸。

颜色模式：

- 参考色：使用每张图案的内置配色。
- 自定义色：保留亮度层次，整体使用视觉控制台颜色。
- 专辑色：根据当前封面主色和辅助色重新映射。

## 性能与可靠性

- 桌面端目标稳定 60 FPS。
- 粒子数随现有性能档位调整，复杂图案不能通过无限增加粒子保证清晰度。
- 强拍动画使用有上限的状态值，不能累积无法释放的时间线或资源。
- 节拍分析未就绪时按内部时间轮播，并在可用后平滑接管。
- 图案切换保持粒子数量与索引稳定，避免频繁创建 GPU Buffer。
- 不访问网络、不上传参考图片、不增加账号、Cookie 或隐私数据。
- 首版不制作通用图案编辑器。

首轮顺序：

2. 玫瑰花束（2026-07-07 已验收）。

每张图案均执行：

1. 在预览页锁定当前图案。
2. 使用 90、120、150 BPM 检查呼吸。
3. 连续触发强拍，确认不抖动、散架或过曝。
4. 检查参考色、自定义色和模拟专辑色。
5. 检查宽屏和较窄窗口构图。
6. 通过 Codex Browser 动态展示。
7. 用户确认后再制作下一张。

## Decision Log

- 采用矢量路径采样，而不是直接对参考截图做边缘检测。
- 采用 GPU 粒子变形，而不是逐粒子 CPU 动画。
- 使用独立预览页逐张动态验收，不要求每次打开完整 Mineradio。
- 预览页使用内置 BPM 和节拍强度模拟，不加载本地音乐。
- 2026-07-07 当前版本收束为三组已验收图案；其它造型下次继续。
- 首个图案为 `MARS CONCERT` 文字与徽标。
- 第二个图案“玫瑰花束”最终采用参考图高亮轨迹离线提取；锁定八朵不规则花瓣、三束 S 形青色花茎、白色星芒和 24,000 粒子配置。
- 第三个图案“人物与猫”采用参考图高亮轨迹离线提取；锁定原始宽高比例、人物暖金色、猫深红色以及独立 `pointSize = 1.30`。
- 正式预设命名为“火星灯光秀”，放在“安魂”之后。
- 正式运行时复用一个 24,000 点 `THREE.Points` 图层和同一组 GPU Buffer；切换图案只更新目标坐标，不重复创建 WebGL 资源。
- 默认保留参考色，同时支持自定义色和专辑封面主色。
- 镜头采用正面构图、轻微纵深和缓慢漂移。
- 歌词保持前景，无人机自动退到后景。
- 2026-07-07 追加设计确认：当前固定二维图案效果不够接近其它可移动镜头预设，后续升级目标改为“3D 无人机雕塑”。
- 采用“分层雕塑化”，而不是全体素云雕塑；原因是能保留 MARS 文字、玫瑰和人物猫的正面识别度，同时补足拖动镜头时的体积感。
- 不采用单纯增加背景星阵或自动镜头旋转；原因是这不能解决图案本体偏二维的问题，且自动旋转会破坏听歌时的稳定构图。
- 图案本体不主动旋转展示侧面；体积只在用户拖动镜头、镜头移动或回正过程中显现。
- 3D 升级优先复用现有 `THREE.Points`、GPU Buffer、轮播和 morph 数据流，不建立大型抽象或通用无人机编辑器。
- 2026-07-08 正式加入当前版本前确认：预览页必须同时支持水平 360°、上下方向翻转、滚轮缩放、双击回正，并保持单颗粒子为稳定圆润点贴图。
